# M10 interpretation reference package

Version: 2026-10-23.1. Engine: m10-reference-engine-1.0.0.

This package is a synthetic reference implementation. Every returned product option is non-actionable and has no dose. No hospital has clinically activated these profiles in ClinRx. Runtime definitions are in `backend/app/services/m10_profiles.py`; JSON files here are review snapshots of those exact definitions.

The device catalogue supports original report capture for TEG 5000 kaolin, heparinase, RapidTEG, functional fibrinogen, native and three PlateletMapping reagent combinations; TEG 6s Global Hemostasis, Lysis, HN and two PlateletMapping cartridges; ROTEM delta liquid and S reagent profiles, sigma Complete and Complete + HEP, and ROTEM platelet. Registry masks have a stated verification level. Additional source-labelled outputs are retained without executable mapping. A source-defined capture vocabulary is not a verified regional export adapter. Current IFUs and representative site exports are needed for operational connectivity.

Eleven explicit reference profiles cover the required settings with at least one positive, no-option and missing-context test per profile. The tests independently name expected values and product families. TEG 6s HN uses a concurrent Clauss fibrinogen product pathway; no CFFH threshold is misrepresented as a validated treatment algorithm. That HN VET-treatment limitation remains open. The sigma Complete trauma profile implements the FEISTY fibrinogen branch only. It does not borrow plasma or platelet triggers from delta. TEG 6s GH cardiac uses the cardiac subset of the RUH Bath non-obstetric protocol, with no lysis branch because the registered GH mask does not supply lysis.

Primary evidence URLs, document sections and provenance are in `sources.json`. The original Zamper liver algorithm Figure 1 was visually inspected: the fibrin and platelet branches require EXTEM A5 <25 mm with FIBTEM A10 respectively <10 or >10 mm. Plasma follows INTEM CT >240 s and HEPTEM CT >= INTEM CT. The figure requires diffuse bleeding and corrected physiological conditions. The source exclusions are required explicit context. There is no INR-only liver replacement rule.

The evaluator preserves observation identity, exact decimal text, original assay, units, qualifiers, state, context, content hashes and source IDs. Duplicate/conflicting observations, different sample/run identities, wrong assay units, pending/invalid results, missing context and explicit stale/cutoff failure cannot satisfy affected rules. Unsupported comparator results remain visible but are not treated as exact values. Paired heparin evidence can block replacement options even when the caller says heparin was excluded.

The source repository gateway must resolve immutable patient-bound inputs and their cutoffs before evaluation; the pure evaluator cannot establish external patient identity or retrieve missing source records. Quantitative dosing, PRBC guidance and PCC/protamine/antifibrinolytic prescribing require separate verified indication/product protocols. No conversion of PCC into plasma or fibrinogen concentrate into cryoprecipitate units is supplied.
