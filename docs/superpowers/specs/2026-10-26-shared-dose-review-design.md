# Shared dose review

Approved intent: implement the reviewed simple mock-up. One shared patient context, affected medicines in the existing chart, one assessment save. No repeated compatible checks. Prescription correction stays a separate explicit source-record workflow.

Scope: existing synthetic browser-local review storage. An append-only patient/encounter log atomically stores the explicitly reviewed patient context and per-order dose review receipts together. Never write or migrate existing patient stores during deployment. Old per-order review logs remain untouched and readable; new shared receipts take precedence only when saved explicitly. No cached-dose authority: recalculate from current exact sources and maintained profiles. Context belongs to the browser assessment, not a fabricated repository clinical fact; label its provenance in Details. Actual recorded/saved time and selected historical review time remain distinct.

The chart shows a concise latest-values/change summary and Review changes. Shared review asks renal stability and support once; other applicable patient fields appear under context details and are never invented. Explicit first-time medicine product/rationale/phase/infusion checks remain available only where not already reviewed or where their dependency changed. Candidate review acknowledgment per affected supported medicine. Unchanged compatible medicines need no duplicate acknowledgment. One reviewer, one Save reviewed assessment button; no per-medicine save buttons. Keep unavailable/unsupported medicines visible with their reasons, never silently approve them.

Shared local context may replace only patient-review assertions and exact source-pin freshness checks, after an explicit browser assessment. It must match repository/patient/encounter, exact latest creatinine/weight and original repository context identity, cutoff and review time. It must never bypass invalid numeric sources, binding, ambiguity, renal-rise/AKI, support, unknown safety, freshness or profile gates. Recompute age/CrCl from its explicit context; do not synthesize source facts. Add the local receipt identity to prescription draft detail; actual source pins remain factual references. Backend commands and dose profiles unchanged.

All-old and new receipts remain available under Details & history. Save must recheck current source/context/medicine/history identities after Web Lock acquisition and check expected bytes for both the new log and legacy records; one synchronous storage write and read-after-write. No partial multi-medicine approval. Malformed/concurrent/unknown writes preserve bytes. Switching patient, cutoff, period, or unmounting cannot save a stale draft. Unrelated snapshot updates retain saved approvals. Navigation remains usable while editing; only pending local save or existing medication/source recovery gates block writes.

Preserve source editor and any pending RF2 context recovery. Existing saved source-context fields may initialize the shared review; a changed numeric/source context requires an explicit new renal assessment. Signed same-cutoff previous-dose history must be confirmed before restoration/save. Existing CrCl/profile/source rules remain unchanged, including current preview freshness limits. Mobile deferred.

Approach chosen: atomic browser assessment alongside existing source records, matching the current preview boundary. Sequential repository-context plus browser saves were rejected because they could partially save and require extra recovery UI. A new server clinical-audit service is beyond this bounded UI correction. Clearing browser data still removes local assessments.
