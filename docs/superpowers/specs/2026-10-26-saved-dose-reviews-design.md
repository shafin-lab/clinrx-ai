# Saved medicine dose reviews

User-approved outcome: unchanged dose suggestions return after reload; review only meaningful changes, preserve unaffected confirmations, never change medication orders automatically. Existing preview/database/read-only sources must be preserved; verify writes only in isolated copies. Mobile checks deferred.

Use a versioned append-only browser review log per repository, patient, encounter and stable prescription identity. This is explicitly a local synthetic-preview review, not a shared authenticated clinical audit record. Save explicitly once with reviewer/time; restore checks only after comparing current dependencies and recomputing the candidate. Keep original exact input references in the review receipt. Never store a dose as authority or restore a prescription from a cached suggestion.

Dependencies: product/formulation/route/basis; prescription indication/schedule/dose/status; shared patient values, renal/support/safety context and existing eligibility reasons; medication-specific exceptional administration history (held/missed/deviating or unknown doses, not routine matching maintenance delivery); cultures; exact maintained profile version/source. Ignore unrelated catalog facts and repository cutoff increases. Reject a different scope, lower cutoff or earlier historical review period. A fresh same-value result may reuse unchanged medicine confirmations only after the existing shared renal-context gate is satisfied. Missing/AKI/dialysis/conflicting/stale evidence continues to hold suggestions.

When relevant inputs differ, retain compatible field selections and product/rationale confirmations, show specific reasons and require explicit Save updated dose review before treating the saved approval as current. Product changes reset product confirmation; culture/indication changes reset rationale; dose-context changes retain known fields and ask focused reconfirmation. An order identity change never inherits approval. Changed evidence cannot be approved by unchecking/rechecking without a current explicit save. Normal reload and unrelated updates do not require checks again.

Saved reviews requiring previous-dose evidence restore only after a bounded same-cutoff history read completes. Use the existing course-history endpoint once for all medicines at that snapshot; failed/stale reads withhold automatic restoration. A first manual review also needs confirmed history before saving. Save uses Web Locks, exact bytes concurrency comparison, current-dependency checks when the lock is acquired, bounded strict JSON and read-after-write. Preserve malformed/concurrent/over-budget bytes; never auto-write on load or discard history.

Approaches considered: session-only checks (fails reload requirement); server audit feature (future shared clinical storage, adds backend/schema scope); selected browser log (fits existing same-browser synthetic reviews without touching patient stores). Authorisation is the user's explicit instruction to implement the described saved-review workflow; no additional approval gate is needed.
